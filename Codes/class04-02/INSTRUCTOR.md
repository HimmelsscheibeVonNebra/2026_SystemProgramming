# 교수자 안내 · 파일 속성

전체 수업 대본은 [class04-02-script.md](../../Presentations/class04-02-script.md)입니다. 실습은 완성 소스의 핵심 분기를 읽고, 실행 전에 예상한 속성을 실제 결과와 비교하는 방식입니다.

## 그림 설명

교안 4–7쪽은 CS 537 원본 그림입니다. 7쪽의 /a/b 디렉토리 표에는 c, 오른쪽 파일 경로에는 c.c라고 쓰여 있으므로 표기 불일치를 알리고 c.c로 읽어 설명합니다. 번호 1–8은 캐시 등을 생략한 읽기 순서이며 실제 물리 I/O 횟수로 외우게 하지 않습니다.

## 핵심 확인 사항

- 기본 file_attr는 lstat이고 --follow는 stat입니다. 기본값을 알려 주지 않고 결과를 섞어 비교하지 않도록 합니다.
- 원본·하드 링크는 st_dev와 st_ino가 같고 링크 수 2입니다. symlink를 추가해도 대상의 링크 수는 늘지 않습니다.
- 링크 문자열 note.txt는 8바이트, ABC와 개행은 4바이트입니다.
- mode_demo는 생성 직후 0644를 보여 준 뒤 fchmod로 0640으로 변경합니다. 최종 조회가 0640인 것은 정상입니다.
- umask 공식은 부모 디렉토리의 기본 ACL이 없는 조건입니다. 소유권 변경을 위해 root를 요구하지 않습니다.
- st_blocks의 Linux 단위는 512바이트입니다. st_blksize와 혼동하지 않도록 합니다.
- 희소 파일은 논리적 크기 1,048,577이 핵심입니다. 할당 블록 수는 파일시스템 정책에 따라 달라질 수 있습니다.
- time_attrs에서 atime과 mtime은 고정값으로 유지되고 권한만 0640으로 변경됩니다. 연속된 ctime이 같아도 해상도 때문에 가능한 결과입니다.
- fd_unlink_demo는 같은 inode·크기를 유지하며 links가 1에서 0으로 바뀝니다. 이름 조회는 실패하고 FD 읽기는 성공합니다.

## 퀴즈 정답

1. 깨진 링크: stat은 대상을 찾지 못해 실패하고 lstat은 링크 자체 조회가 가능합니다.
2. st_mode: 종류·권한·특수 비트를 함께 포함하므로 목적에 맞게 마스크하거나 매크로로 판정합니다.
3. 0666 & ~0027 = 0640입니다.
4. chmod는 inode 상태를 바꾸며 파일 내용 변경을 뜻하지 않습니다.
5. 이름을 지워도 열린 FD가 파일을 참조할 수 있습니다.

## 설명을 평가하는 기준

실제 배점은 수업 운영에 맞게 정합니다. 수치의 일치보다 단위·의미·작업 전후 관계를 봅니다. 조회 실패 후 구조체를 사용하지 않는지, 음수 반환과 errno를 확인하는지, 내용과 속성을 구별하는지 확인합니다.

## 진행 문제 해결

- RUN이 비어 있음: 실습 1의 같은 터미널을 사용했는지 확인하고 새 임시 폴더에서 시작합니다.
- mode_demo 재실행 실패: O_EXCL로 기존 이름을 보호하므로 새 디렉토리에서 재실행합니다. 실패 이전에 생성된 파일은 남을 수 있습니다.
- Ubuntu stat -c가 macOS에서 실패: GNU coreutils 명령 차이입니다. C 예제 또는 macOS stat 형식을 사용합니다.
- atime이 예상대로 바뀌지 않음: 마운트 정책을 확인합니다. 읽을 때마다 갱신된다는 가정으로 채점하지 않습니다.
- EACCES 실험이 root에서 성공: root·capability가 기본 권한을 우회할 수 있으므로 일반 사용자로 수행합니다.

make check는 전용 임시 디렉토리에서 실행하며 테스트 파일을 정리합니다. 권한 000의 파일도 경로 검색이 가능하면 stat이 성공할 수 있다는 경우와, 부모 검색 권한이 없는 실패 경우를 각각 검사합니다.
