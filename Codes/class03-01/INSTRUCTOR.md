# 교수자 진행안

120분: 복습 10, 파일 이해와 생성 25, 쓰기 20, 휴식 10, 읽기 20, 위치 수정 25, 정리 10.
설명·시연·학생 실행을 각 프로그램 섹션 안에서 진행한다.

## 진행

1. Hello World 컴파일과 Makefile을 회상하고 >, >>를 비교한다.
2. 파일 내용·메타데이터·경로·종류를 먼저 설명한다. cat/od와 ls/stat을 비교한 뒤 file_create로 FD, open/close, O_EXCL, 권한을 연결한다.
3. file_write에서 O_TRUNC/O_APPEND를 비교한다. write_all은 제공 함수로 사용한다.
4. file_read에서 실제 읽은 길이, EOF, 오류를 구별한다.
5. file_seek에서 읽기로 변한 오프셋을 되돌려 수정한다.

핵심 구현만 슬라이드에 발췌했다. 완성 소스에는 인자 검사와 자원 정리를 포함한다.
file_seek의 strtoimax와 goto done은 미리 제공하고 학생은 lseek/read/write 흐름에 집중한다.
SEEK_END 수정이 부담스러우면 교수가 인자 처리 변경을 시연한다.

## 정답

- create 성공 0바이트, 재생성 종료 1이고 기존 데이터 보존.
- 0666과 umask 022/027: 0644/0640, 기본 ACL 없음 전제.
- truncate XY, append ZZ 후 XYZZ, 4바이트.
- O_TRUNC 제거 시 XYCDEFGHIJ, 10바이트.
- 빈 파일 read 0과 프로그램 종료 0, 없는 파일 open -1과 프로그램 종료 1.
- 32바이트 파일: 버퍼 16이면 보통 16,16,0 / 7이면 7,7,7,7,4,0.
- 위치 3에 XY: ABCXYFGHIJ, 10바이트. 수정 전 출력은 DEFGHIJ.
- 이어서 위치 0에 ZZ: ZZCXYFGHIJ. 위치 10에 !: ZZCXYFGHIJ!, 11바이트.
- SEEK_END -2에 XY(새 10바이트 원본): ABCDEFGHXY.
- 10바이트 파일 offset 12에 Z: 크기 13, 사이 두 바이트 0.
- lseek(fd,0,SEEK_CUR)는 성공 시 현재 위치를 반환한다.
- lseek는 새 위치를 반환하므로 0도 성공이다. 실패는 (off_t)-1이다.

## 수업 중 유의할 설명

FD 0도 유효하다. read는 NUL 종료를 붙이지 않는다. 짧은 읽기만으로 EOF를 판단하지 않는다.
O_APPEND에서는 lseek 후에도 write가 끝에 기록한다. 파일 수정은 삽입이 아니다.
write와 close 성공만으로 영구 저장 완료를 보장하지 않는다.
Linux에서 close 실패를 무조건 재시도하지 않는다.
file_seek는 독점적으로 사용하는 일반 실습 파일을 전제로 한다. 동시 편집·잠금은 후속 내용이다.

## 파일 기초 설명의 확인 질문

- 빈 파일도 존재하는가? 그렇다. 내용은 0바이트지만 메타데이터가 있다.
- ABC 뒤 개행이 있으면 몇 바이트인가? ASCII에서 4바이트다.
- .txt로 이름을 바꾸면 텍스트로 변환되는가? 아니다. 이름 변경은 바이트 형식 변환이 아니다.
- 같은 note.txt라도 다른 파일일 수 있는가? 그렇다. 디렉터리와 현재 작업 경로를 확인한다.
