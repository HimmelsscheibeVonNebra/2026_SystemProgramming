# Class03-02 교수자 안내

## 운영

슬라이드 1–6 복습 15분, 7–13 read 20분, 14–21 write_all 25분, 22 휴식 10분,
23–30 파일 복사와 테스트 40분, 31–33 퀴즈·제출 10분. 총 120분.

먼저 반환값을 예측하게 한 다음 실행한다. student/io_helpers.h의 초기 ENOSYS 실패는 의도했다.
정답 io_helpers.h는 학생이 구현한 다음 비교한다. make test는 완성본 테스트이며 학생 구현 평가는 make test-student를 사용한다.
학생 구현의 통합 검사는 make file_copy_student 후 python3 test_copy.py file_copy_student로 실행한다.

## 핵심 해설

- 10바이트를 4바이트 버퍼로 읽기: 보통 4,4,2,0. 3바이트 버퍼는 3,3,3,1,0.
- 쓰기 테스트 요청 (위치, 길이): (0,10), (4,6), (4,6), (6,4). 누적 기록: 4,4,6,10.
- EINTR은 미처리 상태에서 재시도. 일부 처리 뒤 양수면 그만큼 진행한다.
- 0바이트 반환은 이 helper의 EIO 정책으로 종료. 무한 반복 방지용 방어 분기다.
- ENOSPC 전에 4바이트를 썼으면 그 내용이 남는다. 함수가 실패를 되돌리지 않는다.
- stale errno 테스트: 성공 후 errno가 남아 있어도 성공 반환값을 우선한다.
- Linux close 오류를 무조건 재시도하지 않는다. 먼저 발생한 I/O 오류는 close 전에 perror로 기록한다.

## 테스트 범위

가짜 write는 함수의 분기를 재현하고 매 호출의 포인터와 길이를 검사한다. 커널에 실제 신호를 보내지 않는다.
통합 테스트는 정상 파일, 빈 파일, 바이너리, 버퍼 경계, 입력 없음, 목적지 오류, 동일 경로와 링크를 확인한다.
실제 Linux ENOSPC는 read_chunks를 /dev/full로 리다이렉션해서 확인한다. macOS에서는 자동으로 건너뛴다.
read의 실제 EINTR 주입, 비차단 FD, fsync, 파일 메타데이터 보존, 원자적 교체는 이번 실습 범위 밖이다.

## 피드백 기준

반환값 분기, 위치·길이 갱신, 오류 전달, 실제 바이트 비교, 실패 원인 설명을 확인한다.
동일 목적지로 반복 실행하면 EEXIST가 정상이다. 새 RUN 디렉터리나 새로운 출력 이름을 사용하게 한다.
학생 starter의 assert 실패를 환경 설치 문제로 오해하지 않도록 안내한다.
